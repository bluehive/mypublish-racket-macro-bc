前章では、演算子を一つ実行する `binop` を見ました。本章では、それを組み合わせてプログラム全体を動かします。完成例は次の式です。

```racket
(check-expect (run (list 5 "d" "*" "p" 1 "-" "p") '())
              (list 25 24))
```

5 を複製して掛けると 25。その値を記録し、1 を引いた 24 も記録します。ここで大切なのは、**入力のトークン列、計算中のスタック、表示する値の列**を区別することです。コードは `code/ch02-arith.rkt` にあります。本章の断片はそのファイルを読み解くためのもので、同名の関数を重複して貼り付ける必要はありません。

## 3.1 入力はすでに分割されたリスト

本書の入力は `"5 d * p"` という一つの文字列ではなく、`(list 5 "d" "*" "p")` です。数は Racket の数値、命令は文字列として渡します。`"5"` は数値の 5 と異なり、本実装では未知の命令になります。

この一つ一つの要素をトークンと呼びます。文字列からトークンを切り出す字句解析は、今回の範囲から外します。入力方法を限定すると、実行の仕組みに集中できるからです。

## 3.2 一歩だけ進める step

`step` の仕事は、トークン一つと現在のスタックを受け取り、次のスタックを返すことです。

```racket
;; step : Token Stack -> Stack
(check-expect (step 7 '()) (list 7))
(check-expect (step "*" (list 3 4)) (list 12))
(check-expect (step "p" (list 12)) (list 12))
```

数なら `push`、四則演算なら `binop` を使います。`"d"` は先頭を複製し、`"r"` は先頭の二つを交換し、`"c"` は空リストを返します。`"p"` はスタックを変えません。表示する値を集める仕事は、次の `run` が担当します。

| トークン | 入力スタックの例 | 次のスタック |
|---|---|---|
| `7` | `(list 3)` | `(list 7 3)` |
| `"d"` | `(list 7 3)` | `(list 7 7 3)` |
| `"r"` | `(list 7 3)` | `(list 3 7)` |
| `"c"` | `(list 7 3)` | `'()` |
| `"p"` | `(list 7 3)` | `(list 7 3)` |

すべての表で、リストの左端がトップです。数を積んだ時刻の順と、リストの並び順は逆になります。

## 3.3 残りの入力を処理する run

```racket
;; run : [List-of Token] Stack -> [List-of Number]
;; トークンを左から処理し、p で観測した値を順に返す
(define (run ts s)
  (cond [(empty? ts) '()]
        [(and (string? (first ts)) (string=? (first ts) "p"))
         (cons (top s) (run (rest ts) s))]
        [else (run (rest ts) (step (first ts) s))]))
```

場合分けは三つです。

1. 入力が空なら、これから表示する値はないので空リストを返す。
2. 先頭が `"p"` なら、現在のトップを、残りの入力から得られる出力列の先頭に付ける。スタックはそのまま渡す。
3. それ以外なら、`step` で次のスタックを計算し、残りの入力をそのスタックで実行する。

`string?` を先に調べるのは、数値に `string=?` を適用しないためです。`and` は左側が偽なら右側を評価しません。

再帰呼び出しでは必ず `(rest ts)` を渡しています。有限の入力なら、その長さが一つずつ減って、最後には空になります。これが、この関数の再帰が終わる理由です。

## 3.4 スタックと出力列を別々に追う

冒頭の入力を手で追ってみます。「出力」は理解のために、その時点までに観測した値を記したものです。実装では `cons` と再帰の戻り値から最終的なリストを組み立てます。

| 処理したトークン | 次のスタック（左がトップ） | ここまでの出力 |
|---|---|---|
| 開始前 | `'()` | `'()` |
| `5` | `(list 5)` | `'()` |
| `"d"` | `(list 5 5)` | `'()` |
| `"*"` | `(list 25)` | `'()` |
| `"p"` | `(list 25)` | `(list 25)` |
| `1` | `(list 1 25)` | `(list 25)` |
| `"-"` | `(list 24)` | `(list 25)` |
| `"p"` | `(list 24)` | `(list 25 24)` |

`run` が返すのは最終スタックではありません。`(run (list 2 3 "+") '())` は、計算しても `"p"` がないので `'()` を返します。また、本書の「表示」は画面への逐次出力ではなく、表示予定の値をリストで返すという意味です。途中でエラーになった場合も、それ以前の値が画面に出るわけではありません。

## 3.5 正常な例と失敗する例

次のテストを、既存ファイルの `(test)` より前に追加して試してください。

```racket
(check-expect (run '() '()) '())
(check-expect (run (list 2 3 "+") '()) '())
(check-expect (run (list 7 "p" "p") '()) (list 7 7))
(check-expect (run (list 9 "c" 4 "p") '()) (list 4))
(check-expect (run (list 3 2 "/" "p") '()) (list 3/2))
(check-error (run (list "p") '()) "stack empty")
(check-error (run (list 1 "+") '()) "stack empty")
(check-error (run (list "?") '()) "unknown token")
```

最後から三つ目と二つ目は、必要な数がスタックにない例です。最後は未定義の命令です。ゼロ除算も実行を止めますが、そのエラー文は Racket に任せています。`check-error` はエラーになることを確かめるテストです。

`3/2` の例は互換性の境界も示します。この実装は Racket の数値演算をそのまま使うため、分数を正確な有理数として扱います。GNU dc の十進精度・scale の規則は実装していません。また、Token の定義外の真偽値やリストを安全に診断する入力検証も未実装です。任意の入力を受け付ける完成品として公開する前に、別の課題として扱いましょう。

## 3.6 小さな練習

まず `(list 8 2 "/" "d" "+" "p")` を手で追い、出力を予想してください。次に `(list 8 2 "r" "-" "p")` を追い、交換によって引き算がどう変わるか説明してください。

答えは順に `(list 8)` と `(list -6)` です。値だけでなく、各命令の前後のスタックも書ければ、再帰の引数が何を表すかを理解できています。

ここまでで、データの表現、一歩の状態変化、入力全体の再帰処理がつながりました。代入を使わなくても、「次の状態」を関数の戻り値と引数で受け渡せます。
