> 初稿。コード断片は学習用です。「こうなるはず」という期待と、実際に動かして確かめた結果は分けて書きます。本章の作成時点では、Racket 上での実行確認は未実施です。

マクロは、**計算する前のプログラムを受け取って、別のプログラムを作る仕組み** です。本書の `(bc 2 + 3 * 4)` は、`(+ 2 (* 3 4))` と同じ意味の式に作り直され、そのあと Racket が計算します。

この章で確かめるのは次の三つです。

1. **何を** 作り直すのか — 「値」と「構文（式の形）」の違い
2. **いつ** 作り直すのか — 「展開時」と「実行時」の分担
3. 作り直しても **意味が壊れないか** — 名前の意味を守る「衛生性」

## 3.1 関数が受け取る値、マクロが受け取る構文

まず普通の関数です。

```racket
(define (twice-value x)
  (+ x x))
(twice-value (+ 2 3))
```

| 行・部分 | 意味 |
|---|---|
| `(define (twice-value x) ...)` | `twice-value`（値を二倍）という関数を作る。材料を `x` と呼ぶ |
| `(+ x x)` | `x` と `x` を足す |
| `(twice-value (+ 2 3))` | 関数を使う。先に `(+ 2 3)` が計算されて、`x` には 5 が入る。答えは 10 |

関数に届くのは 5 という **値** だけです。それが足し算から来たのか、最初から 5 と書いてあったのか、関数には区別できません。

次はマクロです。これらの小さな例は、別の `#lang racket` の練習用ファイルで試してください。

```racket
(define-syntax-rule (twice-form expression)
  (+ expression expression))
(twice-form (+ 2 3))
```

| 行・部分 | 意味 |
|---|---|
| `(define-syntax-rule (twice-form expression) ...)` | `twice-form`（形を二回）というマクロを作る。届いた式を `expression` という箱に入れる |
| `(+ expression expression)` | 作り直した後の形。箱の中の式を **二か所に** 書き写す |
| `(twice-form (+ 2 3))` | 箱には値 5 ではなく、`(+ 2 3)` という **式の形** が入る |

このマクロは、次の式を作ります。

```racket
(+ (+ 2 3) (+ 2 3))
```

どちらも答えは 10 ですが、`(+ 2 3)` を計算する回数が違います。関数の例では 1 回、マクロの例では 2 回です。もし式が「画面に文字を表示する」ような動きを含んでいたら、マクロでは 2 回表示されてしまいます。Scratch でいえば、「〜と言う」ブロックをコピーして二か所に置いたのと同じです。だから「マクロなら速い」「関数と同じだから安全」とは決めつけられません。**作った式の中で何回計算されるか** を確かめる必要があります。

bc の初期版は数しか受け付けないので、すぐにこの問題が起きるわけではありません。将来、関数呼び出しなどを許すときに大事になる観点です。

## 3.2 define-syntax-ruleを一行ずつ読む

```racket
(define-syntax-rule (add left right)
  (+ left right))
```

| 部分 | 役割 |
|---|---|
| `define-syntax-rule` | 「見本の形」と「作り直す形」を並べるだけでマクロを作れる、いちばん簡単な命令 |
| `add` | 新しく作る書き方の名前 |
| `left`、`right` | 使う人が書いた式が入る箱（**パターン変数**） |
| `(+ left right)` | 作り直した後の形（**テンプレート**＝ひな型） |

`(add 2 (* 3 4))` なら、`left` に `2`、`right` に `(* 3 4)` が入ります。マクロは答えの 14 を返すのではなく、14 を計算できる **式** を作ります。

ただし、この簡単な命令だけでは `(bc 2 + 3 * 4)` の「掛け算が先」を判断できません。式の長さを数えたり、どこに演算子があるか調べたりする処理を書きたいので、本書ではもっと自由に書ける `define-syntax` を使います。

## 3.3 構文オブジェクトは「形＋名前の文脈＋位置」

構文オブジェクトには、式の形だけでなく、「この名前はどの定義を指しているか」（**文脈**）や、「ファイルの何行目に書いてあったか」（**ソース位置**）も入っています。ただの文字列やリストにはない、大事な情報です。

```racket
(syntax->datum #'(+ 2 3))
;; 観察したいデータ: '(+ 2 3)
```

| 部分 | 意味 |
|---|---|
| `#'(+ 2 3)` | `(+ 2 3)` を計算せず、構文オブジェクトとして作る。`#'` は `syntax` の省略形 |
| `syntax->datum` | 構文オブジェクトから文脈や位置をすべて捨てて、ただのデータ（datum）にする |
| `;; ...` | `;` から後ろは **コメント**（人間向けのメモで、実行されない） |

ただのデータにすると形は見やすくなりますが、`+` がどの定義を指すかという情報は消えます。

そこで本書の実装では、全部をデータにせず、`syntax->list` で一段だけ中身を取り出します。

```racket
(syntax->list #'(2 + 3))
;; 2、+、3それぞれを包んだ構文オブジェクトのリスト
```

| 部分 | 意味 |
|---|---|
| `#'(2 + 3)` | 括弧の式を構文オブジェクトとして作る |
| `syntax->list` | 外側の包みを一枚だけはがし、中の要素を「構文オブジェクトのリスト」にする |

中の要素は包まれたまま残ります。括弧の中にさらに括弧がある場合も、それは一つの構文オブジェクトとして残り、必要になったときにもう一度中へ入ります。括弧の形でないもの（たとえば数の `2`）を渡すと `#f` が返ります。第2章の `nested` は、この性質を使って「括弧のかたまりかどうか」を見分けています。

## 3.4 bcマクロの入口を読む

`code/bc.rkt` の入口です（抜粋なので、この部分だけでは実行できません）。

```racket
(define-syntax (bc stx)
  (syntax-case stx ()
    [(_ token ...)
     (compile-infix (syntax->list #'(token ...)) stx)]))
```

| 部分 | 本書での意味 |
|---|---|
| `(define-syntax (bc stx) ...)` | `bc` というマクロを作る。使われた式全体を `stx` として受け取る |
| `stx` | たとえば `(bc 2 + 3 * 4)` 全体の構文 |
| `syntax-case` | 受け取った構文を見本（パターン）と見比べる。Scratch の「もし〜なら」を形で判断する版 |
| `()` | 特別扱いする名前（リテラル）はない、という指定 |
| `_` | その位置は気にしない、という印。ここでは `bc` という名前の位置 |
| `token ...` | 後ろに続く 0 個以上の要素を、まとめて `token` として受け取る |
| `#'(token ...)` | 受け取った要素を並べ直した構文 |
| `(syntax->list ...)` | それを構文オブジェクトのリストにする |
| `(compile-infix ... stx)` | 第2章の変換関数に渡す。エラー表示用に `stx` も一緒に渡す |

`...` は「適当に省略した」という意味ではなく、「くり返し」を表す記号です。0 個でも一致するので、`(bc)` も入口は通ります。そのあと `compile-infix` が「空の式です」とエラーにします。

入口の `syntax-case` 自体は、掛け算が先だということを知りません。四則演算のルールは補助関数（第2章で読んだ部分）が担当しています。

## 3.5 展開時に形をつくり、実行時に計算する

本書の実装では、`compile-infix` などの補助関数を `begin-for-syntax` の中に書いています。また、補助関数で使う機能を次のように読み込みます。

```racket
(require (for-syntax racket/base racket/list))
```

| 部分 | 意味 |
|---|---|
| `require` | ほかの部品（ライブラリ）を読み込む |
| `for-syntax` | 読み込んだ部品を **マクロが式を作り直すとき** に使えるようにする |
| `racket/base` | Racket の基本的な機能 |
| `racket/list` | リスト操作の機能（第2章の `take` や `drop` など） |
| `begin-for-syntax`（コード本体にある） | この中に書いた関数を、作り直しのときに使う道具として置く |

ふつうにプログラムを実行する段階を **フェーズ0**、マクロが作り直しをする段階を **フェーズ1** と呼んで区別します。これは「マクロの処理は必ず最初に一度だけ走る」という意味ではありません。展開・コンパイル・モジュール（ファイル単位の部品）の使い方に関係する区別です。

| 時点 | 本書で担当する処理 | その時点でできあがるもの |
|---|---|---|
| 読み込み | Racket の読み取り係（reader）が括弧や数を読む | 入力の構文 |
| マクロ展開 | 演算子と優先順位を調べて組み替える | 計算式の構文 |
| 実行 | 組み替えた計算式を計算する | 14 などの答え |

`compile-infix` という名前に compile（コンパイル）とありますが、機械語を作るわけではありません。Racket がこの先も処理できる構文に変換する、小さな翻訳係です。

また、プログラムの実行中にキーボードから受け取った文字列は、このマクロにそのまま渡せません。`(bc "2 + 3")` は初期版ではエラーです。文字列を受け付けるには、別に文字を読む仕組み（パーサー）と計算方法を設計する必要があります。

## 3.6 構文を組み立てる #` と #,

実装は左右の式を変換したあと、演算子ごとに次のような構文を作ります。

```racket
#`(+ #,left #,right)
```

この式は、`left` と `right` が用意されている変換処理の中（第2章の部品4）で使います。

| 部分 | 意味 |
|---|---|
| `` #` `` | `quasisyntax` の省略形。構文の **ひな型** を作る。基本的には書いたとおりの形になる |
| `(+ ... ...)` | ひな型の形。足し算の式 |
| `#,left` | `unsyntax` の省略形。ひな型のこの位置に、変数 `left` に入っている構文を **差し込む** |
| `#,right` | 同じく、`right` の構文を差し込む |

Scratch でいえば、「( ) + ( )」ブロックの空いている穴に、別に作っておいたブロックをはめ込む操作です。`left` が `2`、`right` が `(* 3 4)` なら、できあがる形は `(+ 2 (* 3 4))` です。文字をつなげて括弧を書いているのではなく、構文を部品として組み立てています。

| 調べる式 | 切る演算子 | 組み立てる形（イメージ） |
|---|---|---|
| `2 + 3 * 4` | 外側の `+` | `(+ 2 (* 3 4))` |
| `8 - 3 - 1` | 右端の `-` | `(- (- 8 3) 1)` |
| `(2 + 3) * 4` | 外側の `*` | `(* (+ 2 3) 4)` |

この表は構造を分かりやすくした図です。`raco expand` の本当の出力には `#%app` などの内部の部品も出てくるので、この表と一文字ずつ同じになるとは限りません。

## 3.7 衛生性 — 同じ綴りでも名前の意味を守る

次は、使う人が `+` という名前に別の関数を割り当ててしまう例です。リポジトリのいちばん上のフォルダに練習用ファイルを作れば試せます。

```racket
#lang racket
(require "code/bc.rkt")

(let ([+ (lambda (a b) 'captured)])
  (bc 2 + 3))
;; 初期実装で期待する値: 5
```

| 行・部分 | 意味 |
|---|---|
| `#lang racket` | Racket 言語のファイルだという宣言 |
| `(require "code/bc.rkt")` | 本書の bc マクロを読み込む |
| `(let ([+ ...]) ...)` | この括弧の中だけ、`+` という名前を別のものにする。Scratch の「このスプライトのみ」の変数に少し似ている |
| `(lambda (a b) 'captured)` | 材料 `a` と `b` を受け取り、何も計算せず `captured`（「乗っ取られた」）という記号を返す、名前のない関数 |
| `(bc 2 + 3)` | その中で bc を使う |
| `;; 初期実装で期待する値: 5` | 期待している答えのメモ |

もしマクロが作った式の `+` が、この偽物の `+` を指してしまったら、答えは 5 ではなく `captured` になります。本書のマクロは、bc.rkt の側で定義された本物の足し算を指す構文を作るので、この取り違えを防げます。名前がどの定義を指すかを、作り直しの後も守る性質を **衛生性**（hygiene）と呼びます。

ここには本書なりの設計の判断もあります。

- **入力側** の演算子は、`syntax-e` で取り出した記号の綴り（`+` という文字の形）で判断し、電卓の記号として扱います。
- **出力側** の演算子は、bc.rkt で定義された本物の計算を使います。

「入力に書かれた `+` が何を指すか」と「作った式の足し算が何を呼ぶか」を、わざと分けているのです。

ただし、衛生性があるからといって、計算の回数・優先順位・数の扱いまで自動で正しくなるわけではありません。それらは別のテストで確かめます。

## 3.8 エラーの時点を区別する

| 入力 | 問題 | 本書で見つける時点 |
|---|---|---|
| `(bc 2 +)` | 右側の数がない | 展開時 |
| `(bc x + 2)` | 今は変数を受け付けない | 展開時 |
| `(bc 2 ^ 3)` | 今は累乗（何乗）を受け付けない | 展開時 |
| `(bc 1 / 0)` | 式は組めるが、0 で割っている | 実行時 |

変換できない式には `raise-syntax-error`（構文エラーを出して止める命令）を使います。元の構文 `stx` を補助関数まで持ち歩いているのは、エラーのときに「入力のどこが悪いか」を示すためです。

`syntax-case` の見本に合ったからといって、電卓の式として正しいとは限りません。「入口で受け取る」「補助関数で中身を確かめる」の二段階になっています。

## 3.9 手元で確かめる順序

リポジトリのいちばん上のフォルダで、次の順に確認します。

```sh
raco test code/bc.rkt
racket code/example.rkt
raco expand code/example.rkt
```

| コマンド | 何をするか |
|---|---|
| `raco test code/bc.rkt` | bc.rkt に書かれたテスト（答え合わせ）を実行する |
| `racket code/example.rkt` | 使用例を実行する。期待する表示は順に 14、20、4 |
| `raco expand code/example.rkt` | マクロを展開した後の式を表示する |

テストでは、優先順位・左結合・分数・衛生性・正しくない式・ゼロ除算を確かめています。本章の作成時点では、これらを実行して合格したという確認は取れていません。

うまくいかないときは、「読み込み」「マクロ展開」「実行時の計算」のどの段階で起きたかを先に分けると、探す場所をしぼれます。

## 3.10 小さな練習と答え合わせ

1. `(bc 10 - 2 * 3)` を、括弧を使う前置記法に書き換えてください。
2. `(bc 12 / 3 / 2)` を左結合で書き換え、答えを予想してください。
3. `twice-form` に「画面に表示する」式を渡すと、なぜ二回表示されることがあるのか説明してください。

答え：① `(- 10 (* 2 3))` で 4、② `(/ (/ 12 3) 2)` で 2、③ひな型の二か所に同じ式を書き写すからです。「マクロだから」ではなく、作った式のどこが計算されるかで説明できれば、この章の目標に届いています。

身近な例では、表計算ソフトの式を「計算の順番の木」に直す処理が似ています。Racket のマクロでは、さらに名前の文脈を守りながら、今ある言語の中に新しい書き方を足せます。
