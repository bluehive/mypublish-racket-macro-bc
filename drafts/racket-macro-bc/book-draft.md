# はじめに — マクロで電卓言語をつくる


この本では `(bc 2 + 3 * 4)` と書ける小さな言語をつくります。実行結果は14です。括弧を使う `(bc (2 + 3) * 4)` は20になります。

学ぶ柱は三つです。入力の構文を受け取ること、優先順位を保って式を組み替えること、展開後のコードを安全に実行することです。言語の入口、変換の規則、結果の検証がそろって初めて、単なる文字の置き換えからプログラムの変換へ進めるためです。

BSL版で扱った dc の逆ポーランド記法から、今回は bc 風の中置記法へ進みます。`#lang racket` と `define-syntax` を使います。すでに読まれたRacketの構文を受け取るため、文字列 `"2+3"` の解析とは別の課題です。

初期版は四則演算と括弧のみです。GNU bc の変数・関数・scaleや入力装置は未実装です。原稿・コードとも初期ドラフトで、実行確認はこれから行います。

# 第1章 構文を受け取り、構文を返す


普通の関数は引数の値を受け取ります。マクロは、評価される前の式を構文オブジェクトとして受け取ります。構文オブジェクトには式の形だけでなく、ソース位置や識別子の束縛の情報もあります。

たとえば中置式 `2 + 3` を `(+ 2 3)` の構文へ変換すれば、実際の足し算はRacketが実行できます。マクロの担当は構文の変換、実行時の担当は数値の計算です。

最小の実験をしてみましょう。

```racket
#lang racket
(define-syntax-rule (add left right)
  (+ left right))
(add 2 3)
```

次に `raco expand code/example.rkt` で、実装したbcマクロの展開結果を確認します。詳細な展開形にはRacket内部の構文も現れます。ここでは、どの算術演算がどの順序で組み合わされているかを探してください。

第3章「マクロの仕組み」で、syntax と datum、衛生性、展開時と実行時の違いを、実装と対応させて詳しく解説します。

参照: [The Racket Guide: Macros](https://docs.racket-lang.org/guide/macros.html)、[Syntax Objects](https://docs.racket-lang.org/guide/stx-obj.html)。

# 第2章 中置式の優先順位を実装する


`2 + 3 * 4` は `(+ 2 (* 3 4))` に変換したい式です。掛け算を先に行うには、弱い演算である足し算を木の外側に置きます。

初期実装 `code/bc.rkt` は、同じ括弧の深さにある演算子のうち、まず右端の `+` または `-` を探します。それがなければ右端の `*` または `/` を探します。見つかった演算子の左右を再帰的に変換します。

右端で分けるのは、同じ優先順位の演算を左結合にするためです。`8 - 3 - 1` は `(- (- 8 3) 1)` になり4を返します。括弧内のリストは一つの要素として扱い、必要になった時にその中へ降ります。

数値だけの式はそのまま返します。変換できない式は `raise-syntax-error` で、計算する前に拒否します。ゼロ除算は構文として正しいため、展開後の実行時エラーです。

確認する観点は、優先順位、左結合、括弧、正確な分数、構文エラーです。単項演算子を別トークンで書く `(bc - 2)` は対象外ですが、負数リテラル `(bc -2)` は使えます。

今後は実装を関数ごとに分解し、追跡表とエラー例を増やします。テストは用意していますが、Racket上の実行確認は未実施です。

# 第3章 マクロの仕組み — 式を読み、組み替え、安全に渡す


> 初稿。コード断片は学習用です。期待する結果と、実際に実行して確認した結果は区別します。本章の作成時点ではRacket上での実行確認は未実施です。

マクロは、**計算する前のプログラムを受け取り、別のプログラムをつくる仕組み**です。本書の `(bc 2 + 3 * 4)` は、意味として `(+ 2 (* 3 4))` に相当する構文へ変換されます。その後、Racketが算術演算を実行します。

この章の柱は、①値と構文の違い、②展開時と実行時の役割分担、③名前の意味を守る衛生性です。この三点を選んだ理由は、「何を変換するのか」「いつ変換するのか」「変換しても意味が壊れないか」を順に確かめられるからです。前章で見た優先順位の処理を、この三つの視点から読み直します。

### 3.1 関数が受け取る値、マクロが受け取る構文

まず普通の関数を考えます。

```racket
(define (twice-value x)
  (+ x x))
(twice-value (+ 2 3))
```

関数を呼び出す前に `(+ 2 3)` が評価され、関数には値の5が渡ります。関数は、その5が足し算から来たのか、数字の5を直接書いたのかを引数だけでは区別できません。

一方、次はマクロです。これらの小例は別の `#lang racket` の学習用ファイルで試してください。

```racket
(define-syntax-rule (twice-form expression)
  (+ expression expression))
(twice-form (+ 2 3))
```

このマクロは `(+ 2 3)` という式の形を受け取り、意味として次の式をつくります。

```racket
(+ (+ 2 3) (+ 2 3))
```

どちらも結果は10ですが、足し算の式を評価する回数が違います。関数の例では引数の式は一度、マクロの例では二度です。表示や状態変更を伴う式なら、この違いは観察できます。「マクロなら速い」「関数と同じだから安全」とは決められません。何回評価するコードを生成したかを確認する必要があります。

bcの初期仕様は数値リテラルだけなので、この問題が直ちに現れるわけではありません。将来、関数呼び出しなどを許すときに重要になる観点です。

### 3.2 define-syntax-ruleを一行ずつ読む

```racket
(define-syntax-rule (add left right)
  (+ left right))
```

| 部分 | 役割 |
|---|---|
| `add` | 新しく定義する構文の名前 |
| `left`、`right` | 利用側の構文が入るパターン変数 |
| `(+ left right)` | 置き換え先を組み立てるテンプレート |

`(add 2 (* 3 4))` なら、`left`に2の構文、`right`に `(* 3 4)` の構文が対応します。マクロは数値14を返すのではなく、それを計算できる式を生成します。

ただし、これだけでは `(bc 2 + 3 * 4)` の優先順位を解析できません。本書では、入力の長さや演算子を調べる処理を書くため、より一般的な `define-syntax` を使っています。

### 3.3 構文オブジェクトは「形＋名前の文脈＋位置」

構文オブジェクトには、式の形だけでなく、識別子がどの定義を指すかという文脈や、ソース位置の情報も含まれます。これは文字列や普通のリストにはない大事な情報です。

```racket
(syntax->datum #'(+ 2 3))
;; 観察したいデータ: '(+ 2 3)
```

`#'` は `syntax` の省略記法です。`syntax->datum` は形を見るのに便利ですが、構文の文脈を持たない通常のデータへ変換します。出力されたリストだけを見ても、`+` がどの定義を指すかは分かりません。

本書の実装は、全体をデータへ変換して組み直す方法を使わず、`syntax->list` で要素の構文オブジェクトを取り出します。

```racket
(syntax->list #'(2 + 3))
;; 2、+、3それぞれを包んだ構文オブジェクトのリスト
```

これは再帰的に全部の包みを捨てる操作ではありません。括弧の中の式は構文オブジェクトのまま残り、解析するときにさらに中へ進めます。`syntax->list` は正しいリスト形でなければ `#f` を返します。実装の `nested` は、この結果を使って括弧の中へ降りています。

### 3.4 bcマクロの入口を読む

`code/bc.rkt` の入口は次の形です。これは抜粋なので、この部分だけでは実行できません。

```racket
(define-syntax (bc stx)
  (syntax-case stx ()
    [(_ token ...)
     (compile-infix (syntax->list #'(token ...)) stx)]))
```

| 部分 | 本書での意味 |
|---|---|
| `stx` | `(bc 2 + 3 * 4)` 全体の構文 |
| `syntax-case` | 入力の構文をパターンと照合する |
| `()` | このパターンで指定するリテラル識別子はない |
| `_` | その位置の要素を受け流す。ここではマクロ名の位置 |
| `token ...` | 後ろに続く0個以上の構文を受け取る |
| `#'(token ...)` | 受け取った要素を含む構文テンプレート |
| `compile-infix` | 中置式からRacket算術式の構文をつくる補助関数 |

`...` は「なんとなく省略した」という意味ではなく、パターンとテンプレートで使う反復の記号です。0個も一致するので `(bc)` も入口のパターンには一致し、その後の `compile-infix` が空の式として拒否します。

入口の `syntax-case` は優先順位を自動的に理解しません。四則演算の規則を実装しているのは、補助関数側です。

### 3.5 展開時に形をつくり、実行時に計算する

本書の実装では、`compile-infix` などの補助関数を `begin-for-syntax` の中に定義しています。また、補助関数が使う機能を次のように読み込みます。

```racket
(require (for-syntax racket/base racket/list))
```

`for-syntax` は、読み込む機能をマクロ変換の側で利用できるようにします。このモジュールの通常の実行をフェーズ0と呼ぶと、変換用の補助処理はフェーズ1に置かれます。これは「すべてのマクロ処理が必ず最初の一度しか走らない」という意味ではありません。展開・コンパイル・モジュールの利用方法に関係する区別です。

| 時点 | 本書の担当処理 | その時点で得るもの |
|---|---|---|
| 読み込み | Racketのreaderが括弧や数値を読む | 入力の構文 |
| マクロ展開 | 演算子と優先順位を解析する | 算術式の構文 |
| 実行 | 生成した算術式を評価する | 計算結果14など |

`compile-infix` の名前にcompileとあっても、本書の関数が機械語を直接生成するわけではありません。Racketがさらに処理できる構文へ変換する、小さなコンパイラの役割です。

また、端末から実行中に受け取った文字列は、このマクロへそのまま渡せません。`(bc "2 + 3")` は初期仕様ではエラーです。文字列入力を追加するときは、別途パーサーと評価方法を設計します。

### 3.6 構文を組み立てる #` と #,

実装は左右の式を変換した後、演算子ごとに次のような構文を生成します。

```racket
#`(+ #,left #,right)
```

この式は `left` と `right` が定義されているマクロ変換用の処理の中で使います。

- `#\`` は `quasisyntax` の省略記法で、構文のひな型をつくります。
- `#,` は `unsyntax` の省略記法で、計算して得た構文をひな型へ差し込みます。

ここで `left` が2の構文、`right`が `(* 3 4)` の構文なら、生成する形は `(+ 2 (* 3 4))` です。文字を連結して括弧を書いているのではなく、構文を部品として組み立てています。

| 解析対象 | 分割する演算子 | 組み立てる形（概念図） |
|---|---|---|
| `2 + 3 * 4` | 外側の `+` | `(+ 2 (* 3 4))` |
| `8 - 3 - 1` | 右端の `-` | `(- (- 8 3) 1)` |
| `(2 + 3) * 4` | 外側の `*` | `(* (+ 2 3) 4)` |

この表は、構造を分かりやすく示したものです。`raco expand` の完全な出力には `#%app` などの内部の構文も現れるため、この表と文字単位で同じになるとは限りません。

### 3.7 衛生性 — 同じ綴りでも名前の意味を守る

次は、利用側が `+` という名前に別の関数を割り当てる例です。リポジトリ直下の学習用ファイルで試せます。

```racket
#lang racket
(require "code/bc.rkt")

(let ([+ (lambda (a b) 'captured)])
  (bc 2 + 3))
;; 初期実装で期待する値: 5
```

生成した式の `+` が利用側の関数にすり替わると、答えは5ではなく `captured` になります。本書のマクロは、定義側の算術関数を指す構文を生成するので、その取り違えを防ぎます。識別子の文脈を保つ仕組みを、衛生性と呼びます。

ここには本書独自の設計判断もあります。入力の演算子は `syntax-e` で取り出した記号の綴りで判定し、DSLの記号として扱います。一方、出力の演算子には定義側の束縛を使います。「入力側の `+` がどんなRacketの変数を指すか」と「生成する加算が何を呼ぶか」を意図的に分けているのです。

衛生性があるだけで、評価回数・優先順位・数値仕様まで正しくなるわけではありません。それらは別のテストで確かめます。

### 3.8 エラーの時点を区別する

| 入力 | 問題 | 本書での検出時点 |
|---|---|---|
| `(bc 2 +)` | 右側の式がない | 展開時 |
| `(bc x + 2)` | 現在は変数を受け付けない | 展開時 |
| `(bc 2 ^ 3)` | 現在は累乗を受け付けない | 展開時 |
| `(bc 1 / 0)` | 算術式は組めるがゼロで割る | 実行時 |

変換できない式には `raise-syntax-error` を使います。元の構文 `stx` を補助関数まで渡しているのは、問題のある入力をエラーの位置と関連付けるためです。

`syntax-case` のパターンに一致したことと、電卓の式として正しいことは同じではありません。入口で受け取り、補助関数で意味のある構造かを調べる、という二段階になっています。

### 3.9 手元で確かめる順序

リポジトリ直下で、次の順に確認します。

```sh
raco test code/bc.rkt
racket code/example.rkt
raco expand code/example.rkt
```

最初は既存のテスト、次は利用例、最後は展開後の式を見るコマンドです。期待する出力は利用例で順に14、20、4です。テストでは、優先順位・左結合・分数・衛生性・不正な構文・ゼロ除算を扱っています。本章作成時点では、これらを実行して合格したという確認は取れていません。

失敗したときは、入力の読み取り、マクロ展開、実行時の計算のどの段階かを先に分けると、探す場所を絞れます。

### 3.10 小さな練習と答え合わせ

1. `(bc 10 - 2 * 3)` を、括弧を含む前置記法へ書き換えてください。
2. `(bc 12 / 3 / 2)` を左結合で書き換え、結果を予想してください。
3. `twice-form` に表示を伴う式を渡すと、なぜ二度表示され得るのか説明してください。

答えは、① `(- 10 (* 2 3))` で4、② `(/ (/ 12 3) 2)` で2、③テンプレートへ同じ式を二か所差し込むためです。単に「マクロだから」ではなく、生成した式のどこが評価されるかで説明できれば、この章の目標に届いています。

身近な比較対象は、表計算の式を計算順序の木へ直す処理です。式の見た目から計算の構造をつくる点は似ています。Racketのマクロでは、さらに識別子の文脈を保ちながら、既存の言語の中へ新しい書き方を追加できます。

# おわりに — bc互換へ進むための境界


初期版では、Racketの構文として書いた算術式をマクロで変換します。次に必要なのは、文字列の字句解析・構文解析と、bc独自の数値仕様です。

マクロ展開時の解析と、実行時にユーザーが入力する文字列の解析は、時点も入力の形も異なります。この区別を保ちながら、変数、代入、関数へ進む計画です。GNU bc完全互換を達成したという意味ではありません。
