この章では、まず **スタック** という考え方を説明し、次に **マクロ** が何をするものかを、短いコードを一行ずつ読みながら確かめます。

## 1.1 スタックとは？ — 皿の山を思い浮かべよう

食堂に積んである **お皿の山** を想像してください。

- 洗ったお皿は、山の **いちばん上** に置きます。
- 使うときも、山の **いちばん上** から取ります。
- 下のお皿を先に引き抜くことはしません。

つまり「**最後に置いたものを、最初に取り出す**」ルールです。これを **後入れ先出し**（英語で LIFO：Last In, First Out）と呼び、このルールで出し入れする入れ物を **スタック**（stack ＝ 積み重ね）と呼びます。

### Scratch のリストで作るスタック

Scratch の「リスト」でもスタックを作れます。「スタック」という名前のリストを作り、次の二つのルールだけで使います。

| やりたいこと | スタックでの呼び名 | Scratch のブロックでの例 |
|---|---|---|
| 上に積む | プッシュ（push） | 「(数) を [スタック] に追加する」（リストの最後に入る） |
| 上から取る | ポップ（pop） | 「[スタック] の (〈スタック〉の長さ) 番目」を読んでから、「(〈スタック〉の長さ) 番目を [スタック] から削除する」 |

リストの **最後** を「山のいちばん上」と決めておくのがポイントです。

比べるために **待ち行列**（キュー）も紹介します。レジの行列は「先に並んだ人から先に出る」（先入れ先出し）ので、スタックとは逆です。Scratch でいえば、「1 番目を削除する」で先頭から取り出すのが待ち行列、「最後を削除する」で末尾から取り出すのがスタックです。

### dc はスタックで計算する

前の本の dc 電卓は、`2 3 4 * +` のように書きます（逆ポーランド記法）。左から一つずつ読み、次のように動きます。

| 読んだもの | すること | スタックの中（左が底、右が上） |
|---|---|---|
| `2` | 数なので積む | 2 |
| `3` | 数なので積む | 2 3 |
| `4` | 数なので積む | 2 3 4 |
| `*` | 上から二つ（4 と 3）を取り、3×4=12 を積む | 2 12 |
| `+` | 上から二つ（12 と 2）を取り、2+12=14 を積む | 14 |

最後に残った 14 が答えです。演算子が後ろに来る書き方では「計算に使う数を、とりあえずどこかに置いておく場所」が必要で、それがスタックです。dc はプログラムを **実行しながら**、このスタックを一つずつ操作します。

### 本書の bc ではスタックが表に出ない

本書の bc は `2 + 3 * 4` という中置記法を、実行する **前に** `(+ 2 (* 3 4))` という Racket の式に組み替えます（これがマクロの仕事です）。組み替えた後の計算は Racket に任せるので、私たちのコードに「スタックに積む・取り出す」という命令は出てきません。dc は「スタックを使って計算する電卓」、本書の bc は「計算できる式を先に組み立てる電卓」と覚えておきましょう。

## 1.2 関数とマクロの違い

**関数** は、材料（引数）を **計算し終わった値** で受け取ります。たとえば `(+ 2 3)` を関数に渡すと、関数に届くのは答えの `5` です。

**マクロ** は、**計算する前の式の形** を受け取ります。`(+ 2 3)` を渡すと、「`+` と `2` と `3` が括弧で囲まれた形」がそのまま届きます。この「式の形」を Racket では **構文オブジェクト**（syntax object）と呼びます。構文オブジェクトには、式の形のほかに、それがファイルのどこに書かれていたか（ソース位置）や、名前がどの定義を指しているか（束縛の情報）も入っています。

Scratch でたとえると、関数は「ブロックを実行した結果の数」を受け取り、マクロは「ブロックそのもの」を受け取って、別のブロックの組み合わせに作り直す道具です。

たとえば中置式 `2 + 3` を `(+ 2 3)` という形に作り直せば、実際の足し算は Racket が実行してくれます。**マクロの担当は形の作り直し、実行時の担当は数の計算**、という分担です。

## 1.3 最小の実験を一行ずつ読む

```racket
#lang racket
(define-syntax-rule (add left right)
  (+ left right))
(add 2 3)
```

| 行・部分 | 何をしているか |
|---|---|
| `#lang racket` | 「このファイルは Racket 言語で書きます」という宣言。ファイルの 1 行目に置く |
| `(define-syntax-rule ...` | 「新しい書き方（マクロ）を一つ決めます」という命令。define は「定義する」、syntax は「構文」、rule は「規則」 |
| `(add left right)` | 決める書き方の **見本**。`add` が新しい名前で、`left` と `right` は「ここに来た式を覚えておく箱」（**パターン変数**） |
| `(+ left right))` | 作り直した後の形（**テンプレート**）。箱に入った式を `+` の後ろに並べる |
| `(add 2 3)` | 作ったマクロを使う行。`left` に `2`、`right` に `3` が入り、`(+ 2 3)` に置き換わる。その後 Racket が計算して 5 になる |

ポイントは、`add` 自身は足し算をしていないことです。`add` は「`(+ 2 3)` という式を作る」だけで、足し算は置き換わった後に Racket が行います。

## 1.4 展開結果を見てみる

マクロが式を作り直すことを **展開**（expand）と呼びます。展開した後の姿は、次のコマンドで見られます。

```sh
raco expand code/example.rkt
```

| 部分 | 意味 |
|---|---|
| `raco` | Racket に付いてくる便利コマンド集 |
| `expand` | 「マクロを展開した結果を見せて」という指示 |
| `code/example.rkt` | 本書の bc マクロを使う例のファイル |

表示される展開形には、`#%app` のような Racket 内部の部品もたくさん現れます。全部を理解する必要はありません。ここでは「どの計算（+ − * /）が、どの順番で組み合わされているか」だけを探してください。

第3章「マクロの仕組み」で、構文（syntax）とただのデータ（datum）の違い、名前の意味を守る **衛生性**、展開するときと実行するときの違いを、実装と対応させて詳しく説明します。

参照: [The Racket Guide: Macros](https://docs.racket-lang.org/guide/macros.html)、[Syntax Objects](https://docs.racket-lang.org/guide/stx-obj.html)。
